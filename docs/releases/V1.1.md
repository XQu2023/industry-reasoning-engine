## New in V1.1

- **Conditional Domain Binding** — industry domain is detected from T0 facts only (`src/domain-binding.ts`) and injected as framing at stage-execution time. Allowed domains: Semiconductor, Cloud Infrastructure, Enterprise Software, Consumer Electronics, Manufacturing, Biotechnology, FinTech, Telecommunications, AI Computing, General Technology, Unknown. Low confidence falls back to General Technology. Domain affects framing only; it never alters or adds facts.
- **Benchmark V2** — expanded from 10 to 20 source-locked cases (IRB-001…IRB-020) spanning consumer platforms, cloud infrastructure, semiconductors, manufacturing, and biotechnology.
- **Source Lock** — every case carries an authoritative T0 source, a frozen `frozenDate`, T0-only `input`, separated later `groundTruth`, and per-category `scoringCriteria`. Cases that could not be locked were replaced (Salesforce → AWS Lambda, Stripe → Apple Watch) rather than invented. Current fidelity: 20/20 PASS.
- **Evaluation Standard** — frozen human rubric (`benchmark/EVALUATION_STANDARD.md`) with fixed IRA weights and scoring principles (T0-only evaluation, Unknown preferred over unsupported certainty, hindsight and hallucination penalized).
- **Regression Runner** — `benchmark/run-benchmark.ts` provides `runBenchmark`, `compareToBaseline`, `loadBenchmarkCases`, and `formatBenchmarkReport`; `scripts/run-irb-baseline.ts` generates all cases for evaluator scoring. Baseline comparison reports improved / unchanged / regressed per case ID.

## Fixed

- **AI Domain Bleed** — the absolute domain declaration (`"Domain: AI Computing Supply Chain only."`) forced AI-computing framing onto non-AI cases, observed in 5 cases at Round 2 Validation (IRB-001, IRB-008, IRB-011, IRB-016, IRB-018). Replaced by input-conditional domain binding per the approved design in `docs/design/SPRINT-001-AI-Domain-Bleed.md` (Approach A). Post-fix bleed count: **0**, with no case regressions and IRA improvements on IRB-003, IRB-008, IRB-011, IRB-012, IRB-014, IRB-016, IRB-017.

## Known Limitations

- **Evidence depth** — Evidence remains the weakest category. Some cases still substantiate the chain mainly by restating T0 announcement facts rather than supporting each causal step independently (notably IRB-007, IRB-016).
- **Weak reasoning links on a few difficult cases** — dense infrastructure and platform cases still carry one incomplete causal link (e.g. IRB-003, IRB-007, IRB-020), typically closed with `Unknown` for the unsupported step.
- Value Reallocation is intentionally conservative; many cases resolve to "Potential value reallocation. Requires later market verification." This is rubric-correct but limits assertiveness.
- Domain detection is signal-based; ambiguous inputs resolve to General Technology (observed on IRB-013) rather than a specific industry.

### Frozen prompts (`src/prompts.ts`)

Stage question text is frozen for all ten stages. Only the shared domain-binding line changed in V1.1.

| # | Stage prompt | Status |
| ---: | --- | --- |
| 1 | `factExtraction` | Frozen |
| 2 | `customerProblem` | Frozen |
| 3 | `leadingSignal` | Frozen |
| 4 | `change` | Frozen |
| 5 | `reasoning` | Frozen |
| 6 | `valueReallocation` | Frozen (Round 2 evidence/hypothesis separation wording) |
| 7 | `winner` | Frozen |
| 8 | `evidence` | Frozen |
| 9 | `verification` | Frozen |
| 10 | `marketBlindSpot` | Frozen |

Shared rules frozen in V1.1: answer only the stage question; keep facts and reasoning separate; never invent facts; return Unknown when evidence is insufficient; no stock-price prediction; no buy/sell advice. Domain line is now conditional on T0-detected domain.
